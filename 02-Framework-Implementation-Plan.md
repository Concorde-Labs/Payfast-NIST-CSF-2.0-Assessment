# Payfast Inc.
## NIST CSF 2.0 - Cybersecurity Implementation Plan

**Prepared by:** Concord Ekwonna  
**Framework:** NIST Cybersecurity Framework 2.0  
**Supporting Reference:** NIST SP 800-53 Rev. 5  
**Document Status:** Proposed Remediation Roadmap

---

## 1. Implementation Overview

This implementation plan translates the cybersecurity gaps identified during Payfast Inc.'s NIST CSF 2.0 assessment into proposed corrective actions.

The plan focuses on improving cybersecurity governance, asset management, authentication, access control, monitoring, incident response, third-party risk management, and operational resilience.

The objectives are to establish clear accountability, prioritize corrective actions, identify expected implementation evidence, and define how remediation effectiveness should be verified.

## 2. Prioritized Remediation Roadmap

| Workstream | NIST CSF 2.0 Function | Proposed Remediation Activities | Accountable Function | Target Timeline |
|---|---|---|---|---|
| Cybersecurity Governance | Govern (GV) | Define cybersecurity responsibilities, establish risk oversight processes, and document security accountability. | Senior Management / Security Lead | 0–30 days |
| Access Management and Authentication | Protect (PR) | Review privileged and employee access, formalize role-change access reviews, and strengthen MFA coverage. | IT / Identity and Access Management | 0–30 days |
| Security Monitoring | Detect (DE) | Establish consistent monitoring requirements for critical payment systems and define alert escalation procedures. | IT Security / Security Operations | 0–60 days |
| Incident Response | Respond (RS) | Develop incident response procedures, define escalation responsibilities, and conduct a tabletop exercise. | Security Lead / Incident Response Team | 0–60 days |
| Third-Party Risk Management | Govern (GV) | Define supplier security requirements, incident notification expectations, and periodic vendor review procedures. | Procurement / Security / Legal | 30–60 days |
| Asset Management | Identify (ID) | Consolidate departmental asset records, identify asset owners, and establish periodic inventory reviews. | IT / Asset Management | 30–60 days |
| Business Recovery | Recover (RC) | Document recovery procedures for critical payment services and perform a recovery exercise. | IT Operations / Business Continuity | 60–90 days |
| Security Awareness | Protect (PR) | Implement recurring security awareness training and track employee participation. | HR / Information Security | 60–90 days |

**Planning Assumption:** Accountable functions and timelines are proposed for portfolio purposes and require management approval before implementation.

## 3. Implementation Phases

### Phase 1: Immediate Risk Reduction (Days 0–30)

Focus on establishing cybersecurity accountability, reviewing high-risk access privileges, strengthening authentication, and initiating improvements to critical security monitoring and incident response.

**Expected outcomes:**
- Defined security responsibilities.
- Initial review of high-risk user access.
- Documented MFA coverage gaps.
- Initial monitoring and incident escalation requirements.

### Phase 2: Control Standardization (Days 31–60)

Formalize repeatable cybersecurity processes and strengthen governance across business functions.

**Expected outcomes:**
- Consolidated asset inventory.
- Documented supplier security requirements.
- Established access review procedures.
- Documented incident response processes.
- Improved monitoring coverage.

### Phase 3: Validation and Continuous Improvement (Days 61–90)

Evaluate the implementation of selected controls and identify remaining weaknesses.

**Expected outcomes:**
- Recovery exercise results.
- Incident response tabletop exercise findings.
- Security awareness completion records.
- Updated remediation tracker.
- Management review of outstanding risks.

## 4. Evidence and Verification Matrix

| Remediation Area | Expected Implementation Evidence | Verification Method |
|---|---|---|
| Cybersecurity Governance | Approved responsibility matrix, risk management procedures, and meeting records | Review documented ownership and management approvals. |
| Access Management | Access review reports, role-change tickets, and MFA configuration records | Sample access changes and review authentication settings. |
| Security Monitoring | Monitoring configurations, alert records, and escalation procedures | Review selected alerts and test escalation workflows. |
| Incident Response | Incident response plan, escalation matrix, and exercise records | Review tabletop exercise outcomes and corrective actions. |
| Third-Party Risk Management | Supplier agreements, security assessments, and incident notification requirements | Sample supplier records and verify documented security obligations. |
| Asset Management | Centralized asset register and ownership records | Reconcile sample inventory records with identified systems. |
| Business Recovery | Recovery procedures, exercise results, and improvement records | Review recovery exercise results against defined recovery objectives. |
| Security Awareness | Training schedule, materials, and completion reports | Verify participation and identify outstanding training requirements. |

## 5. Remediation Tracking and Closure Criteria

Each remediation activity should be tracked using the following fields:

- Finding or workstream reference.
- Assigned owner.
- Agreed corrective action.
- Target completion date.
- Implementation status.
- Supporting evidence.
- Verification result.
- Residual risk and approval, where applicable.

**Closure Criteria:** A remediation item should be closed only when the corrective action has been implemented, supporting evidence has been reviewed, and verification confirms that the identified gap has been adequately addressed.

Unresolved weaknesses should remain open or be escalated for documented risk acceptance by an authorized decision-maker.

## 6. Success Measures

The following indicators are proposed to monitor implementation progress:

| Performance Indicator | Measurement |
|---|---|
| Asset Inventory Coverage | Percentage of identified in-scope assets recorded in the centralized inventory |
| Access Review Completion | Percentage of required access reviews completed within the approved timeframe |
| MFA Coverage | Percentage of in-scope accounts protected by required MFA controls |
| Monitoring Coverage | Percentage of designated critical systems covered by approved monitoring |
| Supplier Review Completion | Percentage of in-scope suppliers assessed against defined security requirements |
| Security Awareness Completion | Percentage of employees completing assigned training |
| Recovery Exercise Completion | Percentage of scheduled recovery exercises completed and documented |
| Remediation Closure Rate | Percentage of due corrective actions verified and closed |

Performance targets should be established after confirming baseline measurements and management expectations.

## 7. Governance and Reporting

The Security Lead should coordinate remediation tracking and provide periodic progress updates to management.

Updates should cover completed actions, overdue activities, unresolved risks, evidence gaps, and decisions requiring management approval.

Following implementation, Payfast should reassess relevant NIST CSF 2.0 outcomes to determine whether the identified gaps between the Current and Target Profiles have been reduced.

## 8. Conclusion

This implementation plan provides a structured approach to improving Payfast Inc.'s cybersecurity governance, operational security, and resilience.

By establishing clear accountability, prioritizing remediation activities, and verifying implementation through documented evidence, Payfast can progressively strengthen its cybersecurity practices and alignment with NIST CSF 2.0 outcomes.
